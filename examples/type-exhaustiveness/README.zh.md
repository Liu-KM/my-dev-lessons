# 新增类别时检查遗漏分支：示例

[English](README.md) | 中文

本示例验证[lesson](../../lessons/type-exhaustiveness.zh.md)中的方法：先复现默认分支把新类别归错，再确认类型检查发现遗漏，最后检查修复后的返回值和计数。示例使用构造数据，不运行真实推理服务或 GPU 实验。

## 运行

在仓库根目录，使用 Python 3.9 及以上的独立环境：

```sh
python -m pip install -r examples/type-exhaustiveness/requirements.txt
python -m unittest discover -s examples/type-exhaustiveness -p 'test_*.py' -v
```

依赖版本和 mypy 配置由本目录文件指定。文档检查不需要这些依赖；CI 在单独步骤安装后运行同一条测试命令。

## 取消请求的分类

| 步骤 | 改动 | 预期结果 |
| --- | --- | --- |
| 复现错误 | 默认分支把取消当作长度截断 | 类型检查通过，分类和计数错误 |
| 加入穷尽检查 | 先处理原来的两种类别 | 类型检查通过 |
| 检查是否发现遗漏 | 只增加取消类别，不改处理函数 | mypy 报告取消类别未处理 |
| 修复 | 补齐取消分支 | 类型检查通过，返回值和计数正确 |

fixtures 目录保留修复前的教学代码，不供业务调用。测试在临时副本中增加类别，保持检查配置不变，并确认实际报错包含遗漏类别和参数类型错误。只有这些预期失败得到确认，整组测试才通过。

其他测试验证：意外值绕过类型检查后会在运行时报错；允许扩展的事件会交给插件处理函数，不会被当作非法类别拒绝。
