# Lesson 双语维护

[English](bilingual-maintenance.md) | 中文

本规范覆盖 `lessons/` 中的全部 Markdown 文件。每条经验使用同目录的英文 `foo.md`、中文 `foo.zh.md` 和一致性记录 `foo.i18n.yaml`。两个版本相互链接，任意一种语言都可以先修改。

## 修改与确认

1. 对照改动更新另一语言，保留结论、条件、来源与验证边界。已有翻译只修改受影响部分。
2. 逐段审阅语义，按[术语约定](../TERMINOLOGY.md)处理词语。命令、参数、路径及 API 标识保留原文，共享代码必须一致；不要为了通过比较而删掉必要信息。
3. 确认两侧一致后，显式记录指定 lesson。下面用本项目的双语维护经验作为实际入口；新 lesson 替换路径。

```sh
python scripts/check_lesson_pairs.py --write lessons/bilingual-consistency-records.md
```

4. 运行检查，并将中英文与记录作为一个改动审阅。

```sh
python scripts/check_lesson_pairs.py
python scripts/check_lessons.py
python -m unittest discover -s scripts -p 'test_*.py'
```

记录命令接受英文、中文或记录文件路径，可以显式列出多条已审阅的 lesson。所有指定配对通过结构与代码检查后才写记录；不带路径的 `--write` 会失败。默认检查只读，不会替维护者确认翻译。

新增经验使用[中文模板](../templates/lesson.zh.md)或[英文模板](../templates/lesson.md)，补齐另一侧、切换链接和记录。重命名时同时处理三个文件和入站链接；删除经验时一起删除三个文件。遗留记录也会导致检查失败。

## 记录格式

记录由脚本生成，不手工编辑。当前格式是固定布局的 YAML：`version: 1`，`sections` 下包含 `intro`、`problem`、`lesson`、`method`、`case` 五项，每项分别保存 `en` 和 `zh` 的 SHA-256 哈希。标题与导语属于 `intro`，三级及更深标题属于所在的二级章节。

哈希覆盖对应部分的全部文本，包括代码与注释；只将 CRLF 换行统一为 LF。两种语言的哈希不需要相等，各自与最近一次确认时的内容比较。只修改一个章节时，其余章节的记录不变。格式校验比较脚本生成的完整文本，不提供通用 YAML 编辑接口。

本项目采用固定四段 lesson 的章节键；DSH 使用通用标题路径，另有代码和生成内容的排除规则。两者不是同一套工具或兼容格式，案例见[中英双语文档一致性维护](../lessons/bilingual-consistency-records.zh.md)。

## 检查范围

| 自动检查 | 仍需人工审阅 |
| --- | --- |
| 中英文及记录是否齐全，切换链接是否指向配对 | 两种语言的结论、条件及证据是否等价 |
| 两侧是否符合各自语言的固定 lesson 章节 | 段落、列表和表格的含义与顺序是否一致 |
| 围栏代码及每个二级章节的行内代码是否一致 | 术语是否合适，表达是否自然 |
| 当前各节内容是否匹配已确认记录 | 命令是否真实存在、运行结果是否符合说明 |

即使两侧都已修改，没有重新记录也会失败。错误翻译经重新记录后仍可能通过，因此不能通过刷新哈希代替语义审阅。CI 运行只读检查，配置文件本身不代表远程检查已经运行或成为必要检查。

README、项目规范、模板与术语表暂不纳入哈希检查范围；已有中英文配对仍应一起维护。此范围不要求给本地 skills、参考克隆或临时草稿建立双语副本。
