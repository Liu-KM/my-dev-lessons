# 新增类别时检查遗漏分支

[English](type-exhaustiveness.md) | 中文

## 问题

一种新结果需要不同处理时，旧函数可能仍能运行，却把它归到已有类别。例如，实验报告需要区分取消请求与达到生成长度上限；若旧代码把所有非成功结果都算作长度截断，加入取消类别后就会统计错误，只测试旧类别又发现不了遗漏。

## 经验

先确认哪些结果需要不同处理，再用类型表达这个要求，并加入穷尽检查，即检查所有可能的类别是否都已处理。类型新增、处理函数未更新时，检查应指出遗漏；补齐分支后恢复通过。主动构造遗漏可以验证检查有效，类别本身是否有必要仍由实际需求决定。

先确定类别能否由插件扩展。所有类别都由本模块定义、且必须逐一处理时，适合穷尽检查；如果接口允许插件新增类别，就应按接口约定处理未知类别。类型检查能发现遗漏，不能判断每个分支的返回值是否正确。

## 方法

1. **确定需求**：沿结果产生、处理到报告输出的路径，确认每种类别为何需要不同处理，以及类型定义与处理函数各由谁维护。封闭集合需要逐一处理；允许插件扩展的接口还需约定未知类别的接收方。
2. **表达要求**：列出合法结果并分别处理，末尾加入穷尽断言。TypeScript 的 `assertNever` 接受 `never` 类型；Python 可配合静态检查器使用 `assert_never`。仍有合法类别未处理时，剩余值不符合断言的参数类型，检查因此报错；仅运行程序或抛出普通异常不能替代这项静态检查。
3. **暴露并补齐缺口**：保持检查配置不变，确认旧类别通过；只加入一个有需求的新类别，处理函数保持原样，确认诊断指出该类别未处理；再补齐分支并确认通过。这里构造的是实现遗漏，导入或语法错误不算验收结果。
4. **验证实际行为**：分别检查返回值、显示文本与统计结果，防止分支齐全却处理错误；允许插件扩展的类别按约定转交或忽略，并验证这条路径。本地和 CI 运行同一测试命令，在临时副本中保留“遗漏时报错、修复后通过”的检查，整组测试成功退出。

Python 示例用 `Literal` 列出允许的类别，以 mypy 严格检查配合 `typing_extensions.assert_never`，验证新增类别是否会暴露遗漏。对于绕过类型检查传入的意外值，运行时断言会报错；它不代替外部输入校验。

## 案例

[DSH 提交 370b5d3aab：增加穷尽断言并区分封闭与可扩展类型](https://github.com/deepseek-ai/deepseek-harness/commit/370b5d3aab7dd751b95c9988661464d83421579a)在流片段组装器中加入穷尽断言。新增一种片段却没有补充处理分支时，类型检查会报错。提交同时明确：插件可以新增的类别应按约定处理，不能一律拒绝；测试还验证了意外值绕过类型检查后会在运行时报错。

本项目的[示例](../examples/type-exhaustiveness/README.zh.md)从“取消请求必须与长度截断分开统计”的要求出发：旧默认分支会误归类，单靠旧类别的测试发现不了遗漏。示例先为原有类别建立穷尽检查，再只新增取消类别，使 mypy 因缺少分支而报错；补齐取消分支后检查通过，行为测试确认分类和计数正确，并用允许插件扩展的事件作对照。这是本项目可复跑的验证顺序，不据此推断 DSH 作者的开发顺序。
