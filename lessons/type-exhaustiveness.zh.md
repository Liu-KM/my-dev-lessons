# 新增类别时检查遗漏分支

[English](type-exhaustiveness.md) | 中文

## 问题

增加一种事件或结果类别后，旧处理函数可能仍能运行，却把新类别当成已有类别。例如，代码把取消请求也统计为达到生成长度上限。只测试原来的类别，就发现不了这种错误。

## 经验

如果处理函数必须区分每一种合法结果，就应列出全部结果类型，分别编写处理分支，并加入穷尽检查，即检查所有可能的类别是否都已处理。这样，新增类型却遗漏分支时，类型检查就会报错。

先确定类别能否由插件扩展。所有类别都由本模块定义、且必须逐一处理时，适合穷尽检查；如果接口允许插件新增类别，就应按接口约定处理未知类别。类型检查能发现遗漏，不能判断每个分支的返回值是否正确。

## 方法

1. 找到类型定义和处理它的函数，确认哪些类别必须逐一处理，哪些允许插件扩展。不要为了让检查通过而禁止原本合法的插件类别。
2. 分别处理每一种类别，最后调用穷尽断言。TypeScript 的 `assertNever` 接受 `never` 类型；Python 可配合静态检查器使用 `assert_never`。如果还有合法类别未处理，传给断言的值就不符合参数类型，检查会报错。仅添加类型注解、运行程序或在末尾抛出普通异常，不能替代这项静态检查。
3. 保持检查配置不变，先确认原来的类别全部通过检查；只新增一种类别，不改处理函数，确认检查报告遗漏的类别；补齐分支后再确认通过。导入失败或语法错误不算发现了遗漏。
4. 分别测试每种类别的返回值、显示文本和统计结果。即使分支齐全，也可能把两个类别的返回值写反。
5. 对允许扩展的接口，说明未知类别由谁处理。按接口约定转交或忽略，并测试合法扩展确实经过这条路径。
6. 本地和 CI 使用同一个测试命令。测试在临时副本中增加类别，确认类型检查因遗漏分支而失败；整组测试则应成功退出。不要修改检查配置来掩盖遗漏。

Python 示例用 `Literal` 列出允许的类别，以 mypy 严格检查配合 `typing_extensions.assert_never`，验证新增类别是否会暴露遗漏。对于绕过类型检查传入的意外值，运行时断言会报错；它不代替外部输入校验。
