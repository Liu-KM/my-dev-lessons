# 检查命令与执行入口保持一致

[English](documentation-check-entry.md) | 中文

## 问题

文档、推送前 hook 和 CI 分别列出检查命令时，新增或改名容易遗漏一处。命令成功退出也不代表执行了所有承诺的检查。修好实现后，审查 skill 仍可能保留旧说明。

## 经验

把检查组合交给一个可执行入口维护，让本地和 CI 调用它；失败向上传递。对文档和 CI 的连接增加明确检查，再通过故意制造错误验证实际入口。检查范围的文字说明仍需依据实现审阅。

## 方法

1. 先确认要覆盖的操作命令及其检查范围；历史案例中的命令不随现行入口改写。
2. 公共入口维护检查顺序和失败退出。文档给出公共命令，hook 和 CI 调用同一入口，避免分别维护子命令列表。
3. 为现行操作文档划定命令块，检查其与公共入口一致。CI 独立运行连接检查，防止公共入口被替换后连检查自身也被跳过。
4. 在临时副本中记录正常、故障、恢复三次结果；断言具体诊断，避免把环境错误误当作成功捕获。

本项目的操作规范见[文档检查](../docs/documentation.zh.md#文档检查)。公共入口只覆盖 Python 文档检查；格式与链接检查仍由 CI 的原有步骤执行。连接检查使用固定格式，不是通用 shell 或 YAML 分析器；不证明整个工作流一定触发，也不防止同时删除检查器和所有调用。审查仍需核对范围、前置条件和检查机制本身的修改。

## 案例

[DSH 提交 fa7d1df6f2：本地和 CI 共用 doc-sync](https://github.com/deepseek-ai/deepseek-harness/commit/fa7d1df6f2c6dbbae32ecbaf0fb8275c407b8828)将原来只在 CI 执行的文档代码块与事件名称检查组合为一个脚本，并接入推送前 hook。统一定义避免两处分别扩充检查列表；提前检查减少推送后才发现遗漏。类型检查所需产物仍是执行前提，共用命令不等于自动消除了环境差异。

[DSH 提交 bcfff6f1ee：纠正审查 skill 中过时的检查说明](https://github.com/deepseek-ai/deepseek-harness/commit/bcfff6f1ee47990a1609d517280a18ea21f35fe1)说明：已有自动检查不代表所有文档语义受保护，审阅者仍需检查配置、默认值及错误码等文字。该案例没有实现全仓库命令漂移检测。

本项目复用现有 Python 环境实现公共入口和固定连接检查，保留本地 hook 与 CI 共用入口、错误退出的机制；额外检查两个操作文档命令块、CI 步骤和 hook 内容。新增连接检查是本项目的实践，不归因于 DSH。

故障实验使用仓库临时副本：文档命令拼错时连接检查应失败；lesson 缺少必要章节时公共入口应失败；CI 换成子检查时独立连接检查应失败。每次恢复原文件后重新运行公共入口。回归测试不递归运行自身，其子进程仍执行其他已有测试。

三项实验的实际退出码均为正常 0、故障 1、恢复 0。文档拼错报告预期公共命令；缺章节报告受影响 lesson 的结构错误；CI 绕过报告缺失的无条件公共入口步骤。恢复使用原始字节，不用放宽规则或刷新配对记录掩盖故障。

验证状态：已核对 DSH 历史提交；本地公共入口通过，58 项测试通过，包含三项故障及恢复实验。另验证了禁用 CI 步骤和删除文档标记会失败。对本机临时仓库执行 Git 推送 dry-run，真实触发 hook 并通过全部检查，退出 0，未实际推送。远程检查及对应提交的结果见 [PR #10](https://github.com/Liu-KM/my-dev-lessons/pull/10)；未永久安装 hook。
