# 检查命令与执行入口保持一致

[English](documentation-check-entry.md) | 中文

## 问题

文档、推送前 hook 和 CI 分别列出检查命令时，新增或改名容易遗漏一处。命令成功退出也不代表执行了所有承诺的检查。修好实现后，审查 skill 仍可能保留旧说明。

## 经验

用一个脚本维护检查顺序，让本地和 CI 调用它；子检查失败时，脚本也应失败退出。另行检查文档、hook 和 CI 是否调用了这个脚本，并故意制造错误，确认检查确实执行。文档声称检查了什么，仍需对照实现审阅。

## 方法

1. 先确认哪些命令供当前操作使用，以及每条命令应该执行哪些检查；历史案例中的命令不随当前脚本改写。
2. 由同一个脚本维护检查顺序和失败退出。文档给出运行该脚本的命令，hook 和 CI 调用它，避免分别维护子命令列表。
3. 标记当前操作文档中的命令块，检查其中是否调用了统一脚本。CI 还应单独检查文档、CI 和 hook 的调用关系；这样，即使有人把统一脚本换成某个子检查，这项检查也不会随之被跳过。
4. 在临时副本中分别运行原始代码、故意改错后的代码和恢复后的代码，记录退出码和报错内容。确认报错指向故意引入的错误，而非环境故障。

本项目的操作规范见[文档检查](../docs/documentation.zh.md#文档检查)。公共入口只覆盖 Python 文档检查；格式与链接检查仍由 CI 的原有步骤执行。调用关系只按约定的固定格式检查，不解析任意 shell 或 YAML，也不证明工作流一定会触发。如果同时删除检查器及其全部调用，这项检查也无法阻止；审阅者仍需核对检查范围、运行前提和检查器本身的改动。

## 案例

[DSH 提交 fa7d1df6f2：本地和 CI 共用 doc-sync](https://github.com/deepseek-ai/deepseek-harness/commit/fa7d1df6f2c6dbbae32ecbaf0fb8275c407b8828)将原来只在 CI 执行的文档代码块与事件名称检查组合为一个脚本，并接入推送前 hook。统一定义避免两处分别扩充检查列表；提前检查减少推送后才发现遗漏。类型检查仍需要预先构建的类型声明文件，共用命令不会自动补齐这些文件。

[DSH 提交 bcfff6f1ee：纠正审查 skill 中过时的检查说明](https://github.com/deepseek-ai/deepseek-harness/commit/bcfff6f1ee47990a1609d517280a18ea21f35fe1)说明：自动检查仍会遗漏文字中的错误，审阅者需检查配置、默认值及错误码等说明。该案例没有自动检测全仓库文档中的命令是否过时。

本项目复用现有 Python 环境，以一个脚本运行检查，并用 `check_doc_entry.py` 检查文档、CI 和 hook 的调用关系。沿用 DSH 的本地 hook 与 CI 共用脚本、失败时非零退出的做法；额外检查两个操作文档命令块、CI 步骤和 hook 内容。这项调用关系检查由本项目增加，DSH 原案例没有实现。

故障实验使用仓库临时副本：文档命令拼错时调用关系检查应失败；lesson 缺少必要章节时公共入口应失败；CI 换成子检查时单独运行的调用关系检查应失败。每次恢复原文件后重新运行公共入口。回归测试不递归运行自身，其子进程仍执行其他已有测试。

三项实验的实际退出码均为正常 0、故障 1、恢复 0。文档拼错报告预期公共命令；缺章节报告受影响 lesson 的结构错误；CI 绕过报告缺失的无条件公共入口步骤。恢复使用原始字节，不用放宽规则或刷新配对记录掩盖故障。

验证状态：已核对 DSH 历史提交；本地公共入口通过，58 项测试通过，包含三项故障及恢复实验。另验证了禁用 CI 步骤和删除文档标记会失败。对本机临时仓库执行 Git 推送 dry-run，真实触发 hook 并通过全部检查，退出 0，未实际推送。远程检查及对应提交的结果见 [PR #10](https://github.com/Liu-KM/my-dev-lessons/pull/10)；未永久安装 hook。
