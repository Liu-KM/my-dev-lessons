# 规则集中维护与查找

[English](rule-ownership-and-discovery.md) | 中文

## 问题

同一条规则出现在项目介绍、Agent 指令、写作模板和专题文档中时，每次修改都需要找全副本。漏改会产生冲突，持续追加解释则让入口文档越来越长。

只删除重复内容也不够：规则搬走后，如果没有清楚的入口，人和 Agent 可能找不到它，仍按记忆操作。重复维护与难以查找需要一起解决。

## 经验

每条规则只有一个主要维护位置，其他位置通过链接引用；同时按任务提供查找入口，并把读取对应规则纳入实际工作流程。内容集中维护，入口可以有多个。

“一个位置”指一个逻辑来源，中英文配对可以共同构成这个来源。简短提示可以重复，但不能在不同文件中各自定义完整要求或新增例外。

## 方法

1. 盘点现有规则，搜索独特措辞及相关概念，找出相似表述。不同写法是否重复了同一条规则、不同要求是否冲突，仍需逐段判断。
2. 按职责确定维护位置，例如文档规范负责写作要求、术语表负责用词、PR 规范负责协作流程。合并重复要求，保留适用条件与必要例外；未决设计不写成现行要求。
3. 删除其他位置的完整副本，改为简短提示和直接链接。在同一个改动中修正旧链接，避免新旧规则并存。
4. 在阅读入口提供“当前任务 → 对应规范”的导航。在 Agent 指令或审阅流程中要求先读取相关规范，再修改或判断内容；不要只依赖记忆或全库搜索。
5. 检查链接是否有效、任务入口是否能找到要求，以及旧位置是否仍有重复定义。对反复膨胀的入口文档，可以增加有针对性的篇幅限制；上限不能代替内容审阅。

例如，lesson 的完整写作要求由文档规范维护，README 只提供“编写 lesson”的入口，模板提供可填写结构并链接规范。修改规则时更新主要维护位置及受影响的模板和检查器，而不是在所有入口重写规则。检查器是规则的执行方式，不是另一份独立规定。

链接检查只能确认目标文件或标题存在，不能判断是否找对了规则；篇幅检查只能发现超限，不能识别所有不同写法的重复规则。规则是否被遵守，仍需检查实际行为并审阅改动。

## 案例

[DSH 提交 `aa36b3b36b`：建立文档职责与篇幅检查](https://github.com/deepseek-ai/deepseek-harness/commit/aa36b3b36bcb46ef3c9d37b23c3145439fd7bf1a)

- **问题与设计**：重复规则与不断追加的说明使常驻文档膨胀。该提交为不同文档层级定义职责，并要求搜索重复措辞、保留一个维护位置、将其他表述改为链接。
- **篇幅检查**：用清单列明文件及其篇幅上限，并将检查接入文档检查脚本；超限或清单中的文件缺失都会失败。它限制指定文档的长度，不能判断全仓库中哪些规则意思重复。
- **证据**：[该版本的文档规范](https://github.com/deepseek-ai/deepseek-harness/blob/aa36b3b36bcb46ef3c9d37b23c3145439fd7bf1a/docs/AGENTS.md)与[检查器](https://github.com/deepseek-ai/deepseek-harness/blob/aa36b3b36bcb46ef3c9d37b23c3145439fd7bf1a/scripts/verify-doc-budgets.ts)。

[DSH 提交 `73dbbb751c`：按修改对象组织审阅规则与入口](https://github.com/deepseek-ai/deepseek-harness/commit/73dbbb751c2ad113cd65d40c99c1942d0c83dc06)

- **整理方式**：将原有规则页改为专题目录，增加“修改什么 → 阅读哪份规则”的导航；专题页链接到类型定义和含义说明，不再次复制。
- **使用方式**：同步修改根目录指令与代码审阅流程，要求先定位并读取相关规则，再审阅改动；同时修正引用和双语配对。
- **证据**：[导航页](https://github.com/deepseek-ai/deepseek-harness/blob/73dbbb751c2ad113cd65d40c99c1942d0c83dc06/docs/defensive-patterns/README.md)与[审阅流程](https://github.com/deepseek-ai/deepseek-harness/blob/73dbbb751c2ad113cd65d40c99c1942d0c83dc06/.agents/skills/dsh-code-review/SKILL.md)。

验证状态：已核对两个 DSH 提交、相关规则与引用变更，未运行其篇幅检查，也未测量整理后的重复率或执行效果。本项目将写作要求与检查说明集中到文档规范，用链接替代 README 和 Agent 指令中的完整定义，并在贡献指南增加任务导航。实际规则更新选取了“验证状态”：在规范中明确区分源码核对、本地执行与远程 CI，模板链接该要求而不独立定义。本地检查验证了链接及六个入口到五个规范目标的查找路径，人工审阅核对了双语内容与规则的剩余定义。这不证明长期执行效果，远程检查记录在对应 PR 中。
